# Obsidian Knowledge Graph

Use this skill when writing code that builds graph nodes/edges from posts, or writes `.md` files into the Obsidian vault.

## Architecture: graphifyy + Custom Frontmatter

We use **`graphifyy[leiden]`** (the open-source graph-from-documents library) as the graph layer:
- Leiden community detection → automatic topic clusters beyond manual taxonomy
- Multi-format export including Obsidian vault (one `.md` per node + `_COMMUNITY_.md` files)
- Built-in YAML injection prevention

Our pipeline **extends** graphifyy's output with richer post-specific frontmatter (external links, comments, source URN, etc.) that graphifyy doesn't know about.

## Node Types

| Type | Label Format | Example |
|------|-------------|---------|
| `post` | `post_{urn_tail}` | `post_7458137957485699072` |
| `topic` | `{topic_name}` | `local_llms` |
| `author` | `{author_slug}` | `abhishek_veeramalla` |
| `external_url` | `url_{domain_slug}` | `url_github_com` |
| `concept` | `{concept_slug}` | `multi_token_prediction` |

Node IDs must be: lowercase `[a-z0-9_]`, deterministic (stable across runs), no random suffixes.

## Edge Relation Types

| Relation | Source | Target | Notes |
|----------|--------|--------|-------|
| `conceptually_related_to` | post | topic | EXTRACTED when classified |
| `authored_by` | post | author | EXTRACTED (always 1.0) |
| `references` | post | external_url | EXTRACTED when URL present in post |
| `semantically_similar_to` | post | post | INFERRED (0.65–0.95) |
| `amplifies` | post | post | INFERRED for reposts/quotes |
| `cites` | post | external_url | INFERRED when content aligns |

---

## Confidence Model (from graphifyy)

| Tag | Score Range | Meaning |
|-----|------------|---------|
| `EXTRACTED` | 1.0 | Directly present in post content |
| `INFERRED` | 0.55 / 0.65 / 0.75 / 0.85 / 0.95 | LLM-inferred, discrete values only |
| `AMBIGUOUS` | 0.1–0.3 | Uncertain, needs human review |

**Never use `0.5` as a confidence score.** INFERRED scores must be one of the five discrete values.

## YAML Injection Prevention (CRITICAL — copy from graphifyy)

All user-generated content (author names, post content snippets, topic names) that goes into YAML frontmatter **must** be passed through `_yaml_str()`:

```python
def _yaml_str(s: str) -> str:
    """Escape a value for safe embedding in a YAML double-quoted scalar.

    Handles backslash, double-quote, all line breaks (\\n, \\r, U+2028, U+2029),
    tab, NUL, and other C0/DEL control characters. Prevents hostile content
    in author names or post text from injecting sibling YAML keys.
    """
    if s is None:
        return ""
    out: list[str] = []
    for ch in str(s):
        cp = ord(ch)
        if ch == "\\":
            out.append("\\\\")
        elif ch == '"':
            out.append('\\"')
        elif ch == "\n":
            out.append("\\n")
        elif ch == "\r":
            out.append("\\r")
        elif ch == "\t":
            out.append("\\t")
        elif ch == "\0":
            out.append("\\0")
        elif cp == 0x2028:   # U+2028 LINE SEPARATOR
            out.append("\\L")
        elif cp == 0x2029:   # U+2029 PARAGRAPH SEPARATOR
            out.append("\\P")
        elif cp < 0x20 or cp == 0x7F:
            out.append(f"\\x{cp:02x}")
        else:
            out.append(ch)
    return "".join(out)
```

Use in every frontmatter field: `f'author: "{_yaml_str(post.author)}"'`

## Post Note Frontmatter Schema

```yaml
---
id: "urn:li:activity:7458137957485699072"
platform: "linkedin"
author: "Abhishek Veeramalla"
subtitle: "Simplifying MLOps | CTO at AKVA"
date_raw: "4d •  "
topics:
  - "[[AI/ML]]"
  - "[[Open Source]]"
source_url: "https://www.linkedin.com/feed/update/urn:li:activity:7458137957485699072/"
external_links:
  - url: "https://fandf.co/3QKK7Rg"
    title: "Oracle AI Hub"
    summary: "10+ production-ready AI applications..."
comments_notable: false
graph_community: "ai_ml_tools"
confidence: "EXTRACTED"
created_at: "2026-05-14"
tags:
  - linkedin
  - "[[AI/ML]]"
---
```

All string values must go through `_yaml_str()`.

## Vault Directory Structure

```
vault/
├── posts/
│   └── {urn_tail}.md          # one file per LinkedIn post
├── topics/
│   └── {TopicName}.md         # MOC (Map of Content) per topic
├── authors/
│   └── {AuthorSlug}.md        # author summary + all their posts
├── _COMMUNITY_{name}.md       # generated by graphifyy Leiden clusters
└── _index.md                  # entry point: links to all topics + stats
```

## Obsidian Wikilink Conventions

- Topic links: `[[TopicName]]` — must match exact topic name in `topic_taxonomy.json`
- Author links: `[[AuthorName]]`
- Post links: `[[post_{urn_tail}]]`
- Cross-vault links use `[[FileName]]` not paths

## MCP-First Rule (Milestone 2+)

After installing the Obsidian MCP server:
1. Use `obsidian_write_file` MCP tool instead of direct `Path.write_text()`
2. Use `obsidian_create_note` for new vault nodes
3. Direct file writes are the fallback only when MCP is unreachable
4. Check `Settings.obsidian_mcp_enabled` before choosing path

Milestone 1 uses direct file writes (MCP not yet installed). Do not block M1 on MCP setup.

## graphifyy Integration Pattern

```python
# After classify_agent completes, serialize to graphifyy format:

nodes = []
for post in posts:
    nodes.append({
        "id": f"post_{post.urn.split(':')[-1]}",
        "label": post.author or "Unknown",
        "file_type": "document",
        "source_file": post.urn,
        "author": post.author,
        "captured_at": post.created_at.isoformat(),
    })

edges = []
for pt in post_topics:
    edges.append({
        "source": f"post_{pt.post_urn.split(':')[-1]}",
        "target": pt.topic_name.lower().replace(" ", "_"),
        "relation": "conceptually_related_to",
        "confidence": "EXTRACTED" if pt.confidence_score >= 0.8 else "INFERRED",
        "confidence_score": pt.confidence_score,
    })

# Write to graphifyy-in/ for processing
Path("graphifyy-in/nodes.json").write_text(json.dumps(nodes))
Path("graphifyy-in/edges.json").write_text(json.dumps(edges))
```
